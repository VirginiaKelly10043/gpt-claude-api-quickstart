## A simple path from zero to first request

**1. Choose the model you need.** Different tasks need different models—text generation, code assistance, image generation, and video generation are not the same job. Compare them in the model catalog instead of guessing from model names.

**2. Get your endpoint and key.** After registration, use the API endpoint and access credentials provided by the platform. Point your existing OpenAI-compatible client or SDK to that endpoint.

**3. Configure and test.** Set your base URL and key, send a minimal request, and confirm the response format matches your expectations before connecting real traffic.

**4. Integrate into your business.** Once the test request passes, route your production workload through the same endpoint.

That flow can be summarized as:

**Choose a model → Check the endpoint → Configure key and base URL → Minimal request → Real integration.**

## When calls fail, there is a direction

No API service is perfect, and debugging is easier when you have a contact path. When submitting a problem, include the model name, endpoint path, HTTP status code, request ID, and a redacted error body. This lets support focus on the actual issue instead of guessing.

| Common issue | What to include in your report |
|---|---|
| Authentication failure | Key configuration, auth method, error body |
| Wrong path / 404 | Request URL, path, model routing |
| Rate limit | Quota, frequency, response message |
| Timeout or abnormal response | Time, request ID, redacted logs |
